# Blueprint: путь от верстальщика к React-разработчику

Плавный план перехода для тех, кто уже уверенно владеет HTML, CSS, BEM, адаптивом и доступностью.
React не заменяет вёрстку — он меняет способ сборки страницы из переиспользуемых частей и добавляет интерактив.
~70% твоих текущих навыков переносятся почти без изменений.

---

## 0. Что у тебя уже есть (сильные стороны)

- Семантичный HTML, правильные теги.
- BEM-нейминг и изоляция стилей.
- Адаптив на Grid/Flex, mobile-first.
- Доступность (aria, видимый фокус, семантика).
- SVG-спрайты, иконки, базовая оптимизация.
- Понимание каскада, специфичности, CSS-переменных.

Это и есть 70% работы React-верстальщика. Меняется только «обёртка».

---

## 1. Ментальный сдвиг

| Было (вёрстка)            | Стало (React)                    |
|---------------------------|----------------------------------|
| Страница целиком          | Дерево компонентов               |
| BEM-блок `.v-btn`         | Компонент `<Button />`           |
| Копипаст с модификаторами | Пропсы (`variant`, `color`)      |
| jQuery-манипуляции DOM    | Состояние (`useState`)           |

Мысль: **не «верстаю страницу», а «собираю из компонентов»**.

---

## 2. Фаза 1 — JSX (неделя 1)

JSX похож на HTML, но с отличиями. Таблица-шпаргалка:

| HTML              | JSX                          |
|-------------------|------------------------------|
| `class="btn"`     | `className="btn"`            |
| `for="name"`      | `htmlFor="name"`             |
| `onclick`         | `onClick`                    |
| `tabindex`        | `tabIndex`                   |
| `style="color:red"` | `style={{ color: 'red' }}` (объект) |
| `<img src="..">`  | `<img src=".." />` (self-close) |
| интерполяция `%{}`| `{выражение}`                |

**Практика:** возьми статичный макет (витрину/дашборд) и просто перепиши разметку в JSX без логики.
Цель недели: не путаться в `className`, `{}` и self-closing тегах.

---

## 3. Фаза 2 — Компоненты и пропсы (неделя 1–2)

Выноси привычные BEM-блоки в компоненты.

```jsx
// Button.jsx
export function Button({ variant = 'flat', color = 'orange', children, ...rest }) {
  const cls = `v-btn v-btn--${variant} v-btn--${color}`;
  return (
    <button className={cls} {...rest}>
      {children}
    </button>
  );
}
```

```jsx
// Использование
<Button variant="flat" color="orange">Adjust</Button>
```

Что освоить:
- `props` и `children`
- композиция (компонент в компоненте)
- разбиение большой страницы на мелкие компоненты

---

## 4. Фаза 3 — Стили в React (неделя 2)

### Вариант А: CSS Modules (рекомендую старт)
Пишешь привычный CSS/BEM, классы изолируются автоматически.

```jsx
import s from './Button.module.scss';

export function Button({ variant = 'flat', color = 'orange', children }) {
  return (
    <button className={`${s.btn} ${s[variant]} ${s[color]}`}>
      {children}
    </button>
  );
}
```

```scss
/* Button.module.scss — твой же CSS */
.btn { padding: 4px 8px; border-radius: 6px; }
.flat.orange { background: #f57c00; color: #fff; }
```

### Вариант Б: styled-components / Tailwind
Освой позже, когда привыкнешь к компонентам. Не обязательно на старте.

## 5. Фаза 4 — Интерактив (неделя 2–3)

Переводи свои jQuery-скрипты на хуки.

```jsx
import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <span>{count}</span>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={() => setCount(count - 1)}>-</button>
    </div>
  );
}
```

Пример миграции твоего слайдера/модалки:
- `$popover.toggleClass('d-none')` → `const [open, setOpen] = useState(false)` + `{open && <Popover/>}`
- обработчики `.on('click', ...)` → `onClick={...}`

Что освоить:
- `useState` (состояние)
- `useEffect` (побочные эффекты, например запросы) — базово
- передача данных вниз через пропсы

## 6. Фаза 5 — Пет-проект (неделя 3–4)

Портируй знакомый макет на **React + Vite**:

```
npm create vite@latest trainer -- --template react
```

Идеи (из прошлых обсуждений):
- Тренажёр флешкарты/квиз (разделы CSS/HTML/React, режимы, localStorage).
- Клон idi-dashboard (карточки, табы, модалки, слайдеры).
- Мини витрина (товары, корзина на `useState`).

Разбей на компоненты: `Card`, `Tabs`, `Modal`, `Button`, `Slider`.
Знакомый дизайн = не тратишь мозг на макет, учишь только React.

---

## 7. Фаза 6 — Углубление (месяц 2)

- Списки и `key`, условный рендеринг (`{cond && <X/>}`, `{cond ? A : B}`)
- Формы и контролируемые инпуты
- Подъём состояния (state lifting)
- `useContext` — вместо пропсов для глубоких деревьев (без Redux)
- Маршрутизация: `react-router-dom` (если несколько страниц)
- Хуки подробнее: `useEffect`, зависимости, очистка

---

## 8. Чего НЕ делать сразу

- ❌ Redux / Zustand / сложные стейт-менеджеры — `useState` хватит надолго.
- ❌ TypeScript на старте — добавь позже, когда освоишь JSX.
- ❌ SSR (Next.js) — сначала чистый клиентский React + Vite.
- ❌ Манипуляции DOM вручную (`document.querySelector`) — это антипаттерн.

---

## 9. Типичные ошибки верстальщика в React

- Ручное изменение DOM вместо состояния.
- Глобальные классы без изоляции (конфликты) → CSS Modules / BEM.
- Инлайн-стили ради «быстро» вместо классов.
- Забытый `key` в `.map()`.
- Попытка верстать «одну большую страницу» вместо компонентов.

## 10. Чек-лист готовности (junior React)

- [ ] Понимаю JSX и не путаю `class`/`className`.
- [ ] Собираю UI из компонентов, а не одним файлом.
- [ ] Стилизую через CSS Modules (или свой BEM).
- [ ] Управляю интерактивом через `useState`.
- [ ] Знаю разницу состояние vs пропсы.
- [ ] Делаю списки с `key`, условный рендеринг.

## Итог

Твой `.v-btn`, `.product-card`, `.number-stepper` станут компонентами за вечер, а весь CSS переедет почти как есть.
«Боязнь React» у верстальщиков обычно ложная: пугает не CSS, а незнакомый синтаксис, который осваивается за пару дней.
Главное — начни с малого: JSX → компонент → стили → состояние → пет-проект.
