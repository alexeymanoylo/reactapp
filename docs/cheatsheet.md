## Тема 1. JSX

- `class` в JSX → **`className`** (атрибут `class` зарезервирован в JS).
- JS вставляется в фигурных скобках: `{count}`, `{items.map(...)}`.
- Теги **самозакрывающиеся**: `<img />`, `<input />` (слеш обязателен).
- **Фрагмент** `<> ... </>` — чтобы `return` вернул несколько элементов без лишнего `<div>` в DOM.

---

## Тема 2. Компоненты и пропсы

- Компонент = функция, возвращающая JSX. Именованный экспорт:
  ```jsx
  export function Card({ title }) {
    return <div>{title}</div>
  }
  ```
- Вызов с пропсом: `<Card title="Товар" />`.
- **children** — вложенный контент между тегами; достаётся как `props.children`.
- Колбэк-пропс (проброс действия вверх):
  ```jsx
  <Card onAdd={fn} />
  // внутри Card:
  <button onClick={() => onAdd(title, price)}>Добавить</button>
  ```
  Обёртка-стрелка нужна, чтобы передать свои аргументы.

- Можно писать свои BEM-имена внутри `.module.css` — конфликтов с другими файлами нет.

## Тема 4. Состояние примитивами (`useState`)

- Объявление: `const [count, setCount] = useState(0)`.
  - `count` — текущее значение (для вывода).
  - `setCount` — функция-сеттер (меняем ТОЛЬКО через неё).
- Изменить: `setCount(count + 1)` (прямое) или `setCount(prev => prev + 1)` (когда новое
  зависит от старого).
- **Нельзя** `count = ...` напрямую.
- `import { useState }` пишется **в КАЖДОМ файле**, где используется хук (не наследуется).
- Паттерны-вариации (закрепляли 5 штук):
  - Счётчик `±1`: `setCount(count + 1)` / `setCount(count - 1)`.
  - Тоггл (булево): `setOn(!on)` — префикс `is`/`on` для булевых (`isToggled`).
  - Reset: `setCount(0)`.
  - Step: `setCount(count + 5)` / `count - 5`.
  - Защита от минуса: `setCount(count > 0 ? count - 1 : 0)`.

## Тема 5. Списки и массивы

- **Массив** = список объектов: `[{ id: 1, name: 'Яблоки' }, ...]`.
- **Вывод** через `.map` (аналог `v-for`):
  ```jsx
  {items.map(item => <li key={item.id}>{item.name}</li>)}
  ```
- **`key` обязателен** у каждого элемента. Бери `item.id` (стабильный). `index` брать НЕ надо —
  при удалении индексы сдвинутся и React запутается.
- **Состояние-массив:** `const [items, setItems] = useState([...])` (можно с готовыми данными
  или пустым `[]`).
- **Добавление — через spread** (НЕ `push`!):
  ```jsx
  setItems([...items, { id: items.length + 1, name: 'Новый' }])
  ```
- **Удаление — через `filter`** (НЕ `splice`!):
  ```jsx
  setItems(items.filter(item => item.id !== id))
  ```
- **Изменение одного элемента** (immutable-апдейт):
  ```jsx
  setItems(items.map(item =>
    item.id === id ? { ...item, done: !item.done } : item
  ))
  ```
  Разбор: для нужного элемента возвращаем КОПИЮ `{ ...item, done: !item.done }`
  (все старые поля + перезаписанное `done`); остальные — как есть. `...item` раскрывает
  старый объект, чтобы не мутировать его «на месте» (иначе React не заметит изменение).
- **Производное состояние** (считаем ИЗ массива, не храним отдельно):
  - `items.length` — общее количество.
  - `items.filter(item => item.done).length` — количество выполненных.
  - `items.reduce((sum, item) => sum + item.price, 0)` — сумма (необязательно).
- **Главное правило:** с массивами всегда строй **НОВЫЙ** массив (spread / filter / map).
  Никогда не `push` / `splice` напрямую — это мутация, React не увидит.
- **Поиск по списку** (например, поиск товаров) = `filter` по полю + `toLowerCase()` с обеих
  сторон (без учёта регистра). Примеры в коде:
  [SearchList.jsx](../app/src/practice/SearchList.jsx),
  [ProductCatalog.jsx](../app/src/practice/ProductCatalog.jsx).
- Другие примеры на массивы:
  [ItemList.jsx](../app/src/practice/ItemList.jsx),
  [FruitList.jsx](../app/src/practice/FruitList.jsx),
  [RemoveList.jsx](../app/src/practice/RemoveList.jsx),
  [ToggleList.jsx](../app/src/practice/ToggleList.jsx),
  [SummaryList.jsx](../app/src/practice/SummaryList.jsx).

## Тема 6. Условный рендеринг

- В React нет `v-if`. Вместо него — JS-выражения в `{ }` (как и везде в JSX).
- **Показать, если истина** (аналог `v-if`):
  ```jsx
  {isOpen && <Modal />}
  ```
  `&&` возвращает правую часть, только когда левая `true`; иначе ничего не рендерится.
- **Выбор из двух вариантов** (аналог `v-if / v-else`):
  ```jsx
  {cart.length === 0
    ? <p>Cart is empty</p>
    : cart.map(item => <div key={item.id}>{item.title}</div>)}
  ```
  Тернарник: `условие ? (да) : (нет)`.
- **Подводные камни:**
  - `{count && <X/>}` при `count === 0` покажет `0` (левая часть «ложная», но `&&`
    возвращает её как есть). Для чисел писать `count > 0 && <X/>` или `count ? <X/> : null`.
  - `if` прямо внутри JSX писать нельзя — только выражения (`&&`, `? :`, `.map`).
    `if` допустим в теле функции ДО `return`.
- **Где в витрине:** «Cart is empty» (len===0), кнопка показать/скрыть описание, переключатель табов.

## Тема 7. Формы и контролируемые инпуты

- **Контролируемый инпут** — значение хранится в состоянии (`useState`), а не в DOM.
  Меняем состояние через `onChange`, показываем через `value={...}`:
  ```jsx
  const [value, setValue] = useState('')
  <input value={value} onChange={e => setValue(e.target.value)} />
  ```
  `e.target.value` — текст, набранный в поле.
- **Форма и отправка:** `<form onSubmit={handleSubmit}>`. В обработчике обязательно
  `e.preventDefault()`, иначе страница перезагрузится:
  ```jsx
  function handleSubmit(e) {
    e.preventDefault()
    // что-то делаем с value
  }
  ```
- **Несколько полей:** либо отдельный `useState` на каждое, либо один объект
  `useState({ title: '', price: '' })` (обновляем через spread:
  `setValue({ ...value, title: e.target.value })`).
- **Подводные камни:**
  - Забыл `value={...}` → инпут «неконтролируемый», не обновляется от состояния.
  - Забыл `onChange` → React warning, инпут становится read-only.
  - В `onChange` пиши `setValue(e.target.value)`, а не `setValue(e)` (нужен `.value`).
  - В `onSubmit` не забудь `e.preventDefault()`.
- **Где в витрине:** поиск товара (инпут + фильтрация списка), форма добавления товара.
- Примеры в коде:
  [UserForm.jsx](../app/src/practice/UserForm.jsx),
  [NameForm.jsx](../app/src/practice/NameForm.jsx),
  [AddProduct.jsx](../app/src/practice/AddProduct.jsx),
  [SubmitForm.jsx](../app/src/practice/SubmitForm.jsx).

## Тема 9. useEffect (база)

`useEffect` — это «побочный эффект»: действие, которое происходит **ПОСЛЕ** того, как
компонент отрисовался. В `return` мы описываем, ЧТО показать (разметку). А эффект — это то,
что надо СДЕЛАТЬ снаружи: таймер, запрос на сервер, подписка, смена заголовка вкладки,
запись в `localStorage`.

**Аналогия с Vue** (чтоб зацепиться):
| Vue | React |
|-----|-------|
| `mounted()` | `useEffect(() => {...}, [])` — один раз при появлении |
| `watch(value, cb)` | `useEffect(() => {...}, [value])` — при изменении `value` |
| `beforeUnmount()` | `return () => {...}` внутри эффекта — очистка перед удалением |

**Синтаксис:**
```jsx
useEffect(() => {
  // код эффекта (ПОСЛЕ рендера)
  return () => { /* очистка */ }
}, [зависимости])
```

**Когда эффект запускается — зависит от массива зависимостей (самое важное!):**
- `[]` — ровно **один раз** после первой отрисовки (монтирование).
- `[a, b]` — при монте И каждый раз, когда `a` или `b` изменились.
- (массив не указан) — после **каждого** рендера. Почти никогда не нужно.

**Пример 1: таймер (массив `[]` + очистка)** — `Clock.jsx`:
```jsx
import { useState, useEffect } from 'react'

export function Clock() {
  const [time, setTime] = useState(new Date().toLocaleTimeString())
  useEffect(() => {
    const id = setInterval(() => setTime(new Date().toLocaleTimeString()), 1000)
    return () => clearInterval(id)   // останавливаем таймер при уходе
  }, [])
  return <div>{time}</div>
}
```

**Пример 2: эффект по зависимости `[count]`** — `TabTitle.jsx`:
```jsx
useEffect(() => {
  document.title = `Count: ${count}`
}, [count])   // перезапускается при изменении count
```
Без `[count]` заголовок встал бы один раз; с `[]` — тоже один раз. `[count]` — именно то, что нужно.

**Очистка (`return`) — зачем и что чистить:**
Эффект часто оставляет «следы» ВНЕ React (таймер, слушатель), которые сами не исчезают,
когда компонент ушёл из DOM. Без очистки — утечки/баги (например, таймер дёргает состояние
удалённого компонента). React вызывает `return` перед повторным запуском эффекта и перед
размонтированием.

| В эффекте создал | В `return` чистишь |
|---|---|
| `setInterval(fn, ms)` → `id` | `clearInterval(id)` |
| `setTimeout(fn, ms)` → `id` | `clearTimeout(id)` |
| `addEventListener(ev, fn)` | `removeEventListener(ev, fn)` (ТУ ЖЕ `fn`!) |
| `fetch` + `AbortController` | `controller.abort()` |
| `new WebSocket` / `.subscribe()` | `.close()` / `.unsubscribe()` |
| чужая библиотека (график/карта) | `.destroy()` |

**Что чистить НЕ надо** (мгновенные, после эффекта ничего не осталось): `setState`,
`document.title = ...`, `console.log`. Там `return` не пиши.

**Как понять, что нужно чистить (без опыта — по типу вызова):**
Перечитай эффект и найди «стартеры» — вызовы, запускающие процесс вне React. Снифф-тест:
**«то, что я создал, живёт ДОЛЬШЕ одного прогона эффекта и находится ВНЕ дерева React?»**
Если да (интервал тикает сам, слушатель висит на `window`) → пиши парный `return`. Если нет
(`setState` просто обновил значение) → не нужно. **Правило безопасности:** на каждый «стартер»
в эффекте есть ровно один парный «стоп» в `return`. Привычка: пиши `return` сразу, рядом.

**Подводные камни:**
- Эффект **не возвращает данные** (только функцию очистки или ничего). Результат клади в `useState`.
- **Нельзя** делать сам `useEffect` async. Если нужен `fetch` — пиши async-функцию ВНУТРИ и вызывай.
- **Бесконечный цикл:** `useEffect(() => { setX(x+1) })` без зависимостей → ререндер → эффект
  снова → … Всегда указывай зависимости.

Примеры в коде:
[Clock.jsx](../app/src/practice/Clock.jsx),
[TabTitle.jsx](../app/src/practice/TabTitle.jsx).

## Синтаксис: круглые `()` против фигурных `{}`

Самая частая путаница новичка. Это две разные вещи.

- **Фигурные `{ }` в JSX = «островок JavaScript».** Когда внутри разметки нужно не текст, а значение/вычисление/код — оборачивай в `{ }`:
  ```jsx
  <p>{count}</p>            // значение
  {items.map(...)}          // выражение
  className={s.card}        // динамический атрибут
  onClick={handleClick}     // значение атрибута — функция (это JS)
  ```
- **Круглые `( )` = обычный JS: вызов функции или аргументы.**
  ```js
  useState(0)              // вызов, аргумент 0
  setName('яблоко')        // вызов, аргумент — строка
  e.target.value           // БЕЗ скобок — просто чтение свойства
  ```

**Ловушка событий:** `onClick`/`onChange` ждут НЕ результат вызова, а ссылку на функцию.
| Написано | Когда вызовется | Ок? |
|----------|-----------------|-----|
| `onClick={handleClick}` | при клике | ✅ |
| `onClick={() => handleClick()}` | при клике (стрелка-обёртка) | ✅ |
| `onClick={handleClick()}` | **сразу при рендере** | ❌ |

`имя()` = «вызови сейчас»; `имя` без скобок = «дай ссылку, вызову потом».

**Вопрос к себе перед каждым `onClick`:** функция должна выполниться СЕЙЧАС (при отрисовке) или ПОТОМ (при клике/вводе)? Потом → имя без скобок либо стрелка `() => fn()`.

## Куда что ставить: поток данных

Когда в голове каша «что где объявлять, что куда передавать, что где ловить» — перечитай эту схему. Одна фраза на всё: **данные текут вниз (пропсы), события — вверх (колбэк-пропсы).**

```
        РОДИТЕЛЬ  (владеет стейтом)
   const [x, setX] = useState(...)
          │
          │ ① данные ВНИЗ:    <Child x={x} />
          │ ② действие ВНИЗ:  <Child onX={setX} />
          ▼
        ДОЧКА  (ловит через пропсы)
   function Child({ x, onX }) {
     показать:  {x}
     изменить:  <button onClick={() => onX(новое)} />
   }
          │
          │ ③ событие ВВЕРХ: вызов onX(данные)
          ▼
   РОДИТЕЛЬ меняет стейт → перерисовка
```

**Алгоритм, когда не знаешь, куда писать (5 шагов):**
1. Данные нужны в нескольких местах? → **держи в общем родителе**.
2. В родителе: `const [x, setX] = useState(начальное)`.
3. Родитель передаёт дочке: `<Child x={x} onX={setX} />`.
4. Дочка ловит: `function Child({ x, onX }) { ... }` и пользуется: `x` — чтобы **показать**, `onX` — чтобы **изменить**.
5. Дочка зовёт `onX(значение)` → родитель меняет стейт.

Любой «подъём состояния» — это просто этот алгоритм. `cart` в витрине, `count` в счётчике, `name` в форме — везде одно и то же.

Примеры в коде (подъём состояния):
[LiftedCounter.jsx](../app/src/practice/LiftedCounter.jsx),
[LiftedName.jsx](../app/src/practice/LiftedName.jsx),
[LiftedActions.jsx](../app/src/practice/LiftedActions.jsx),
[LiftedList.jsx](../app/src/practice/LiftedList.jsx) (намеренно «недоделан» — ищи обрыв связи),
[Cart.jsx](../app/src/practice/Cart.jsx).

**Про параметры (откуда берётся `item`/`e`):** имя в скобках функции — это **параметр**, «пустое место под данные». Значение подставляется в момент вызова. `addToCart = (item) => ...` — `item` наполняется тем объектом, который передали при вызове (`onAddToCart({ id, title, ... })`). То же самое с `e` в обработчиках: React сам кладёт событие в `e` при клике. Имя параметра произвольное.

## Суть: как строить компоненты (метод)

Когда голова забьётся — возвращайся сюда. Весь React упирается в **односторонний поток данных**:

```
родитель ──props (данные ВНИЗ)──▶ ребёнок
родитель ◀──callback (событие ВВЕРХ)── ребёнок
```

Ребёнок НЕ меняет state родителя напрямую — он зовёт колбэк, родитель меняет свой state, React перерисовывает дерево. Именно в этом и есть «кайф работающего компонента».

**Перед написанием любого компонента задай себе 3 вопроса:**

1. **Кто владеет данными?** → там и `useState`. (Корзина нужна Store → state в Store.)
2. **Что ребёнок должен сообщать родителю?** → на это делаешь пропс-колбэк (`onAddToCart`).
3. **Что нужно только самому ребёнку?** → локальный `useState` внутри (`selectedSize`, `isFavorite`).

**Две технические привычки (рефлексы):**
- Пропсы — **всегда один объект**: `function Child({ x, onX }) { ... }`. Не `(props, onX)` — второго аргумента не бывает.
- Списки — через `.map` с `key` (см. Тему 5).

**Форма типичного компонента:**
- сигнатура ловит пропсы через деструктуризацию `{ a, onA }`;
- достаём нужное из пропсов и ставим локальный `useState`, если надо;
- в JSX: данные из пропсов/state для показа, обработчики `onClick`/`onChange` вызывают либо `setX`, либо пропс-колбэк;
- списки — `.map` с `key`.

Запомни: 90% «магии» React — это три вопроса выше + две привычки. Остальное (эффекты, контекст, роутинг) — надстройки, а фундамент именно такой. Если работает — значит, поток данных замкнулся: данные вниз, событие вверх.
