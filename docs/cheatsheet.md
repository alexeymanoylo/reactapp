## Тема 1. JSX

- `class` в JSX → **`className`** (атрибут `class` зарезервирован в JS).
- JS вставляется в фигурных скобках: `{count}`, `{items.map(...)}`.
- Теги **самозакрывающиеся**: `<img />`, `<input />` (слеш обязателен).
- **Фрагмент** `<> ... </>` — чтобы `return` вернул несколько элементов без лишнего `<div>` в DOM.

---

## Тема 2. Компоненты и пропсы

- Компонент = функция, возвращающая JSX. Именованный экспорт:
  ```jsx
  export function Card({ title }) {
    return <div>{title}</div>
  }
  ```
- Вызов с пропсом: `<Card title="Товар" />`.
- **children** — вложенный контент между тегами; достаётся как `props.children`.
- Колбэк-пропс (проброс действия вверх):
  ```jsx
  <Card onAdd={fn} />
  // внутри Card:
  <button onClick={() => onAdd(title, price)}>Добавить</button>
  ```
  Обёртка-стрелка нужна, чтобы передать свои аргументы.

## Тема 3. CSS Modules (стилизация)

- Импорт: `import s from './Card.module.css'`.
- Классы изолируются автоматически: `className={s.card}` (аналог `<style scoped>` из Vue).
- Можно писать свои BEM-имена внутри `.module.css` — конфликтов с другими файлами нет.

## Тема 4. Состояние примитивами (`useState`)

- Объявление: `const [count, setCount] = useState(0)`.
  - `count` — текущее значение (для вывода).
  - `setCount` — функция-сеттер (меняем ТОЛЬКО через неё).
- Изменить: `setCount(count + 1)` (прямое) или `setCount(prev => prev + 1)` (когда новое
  зависит от старого).
- **Нельзя** `count = ...` напрямую.
- `import { useState }` пишется **в КАЖДОМ файле**, где используется хук (не наследуется).
- Паттерны-вариации (закрепляли 5 штук):
  - Счётчик `±1`: `setCount(count + 1)` / `setCount(count - 1)`.
  - Тоггл (булево): `setOn(!on)` — префикс `is`/`on` для булевых (`isToggled`).
  - Reset: `setCount(0)`.
  - Step: `setCount(count + 5)` / `count - 5`.
  - Защита от минуса: `setCount(count > 0 ? count - 1 : 0)`.

## Тема 5. Списки и массивы

- **Массив** = список объектов: `[{ id: 1, name: 'Яблоки' }, ...]`.
- **Вывод** через `.map` (аналог `v-for`):
  ```jsx
  {items.map(item => <li key={item.id}>{item.name}</li>)}
  ```
- **`key` обязателен** у каждого элемента. Бери `item.id` (стабильный). `index` брать НЕ надо —
  при удалении индексы сдвинутся и React запутается.
- **Состояние-массив:** `const [items, setItems] = useState([...])` (можно с готовыми данными
  или пустым `[]`).
- **Добавление — через spread** (НЕ `push`!):
  ```jsx
  setItems([...items, { id: items.length + 1, name: 'Новый' }])
  ```
- **Удаление — через `filter`** (НЕ `splice`!):
  ```jsx
  setItems(items.filter(item => item.id !== id))
  ```
- **Изменение одного элемента** (immutable-апдейт):
  ```jsx
  setItems(items.map(item =>
    item.id === id ? { ...item, done: !item.done } : item
  ))
  ```
  Разбор: для нужного элемента возвращаем КОПИЮ `{ ...item, done: !item.done }`
  (все старые поля + перезаписанное `done`); остальные — как есть. `...item` раскрывает
  старый объект, чтобы не мутировать его «на месте» (иначе React не заметит изменение).
- **Производное состояние** (считаем ИЗ массива, не храним отдельно):
  - `items.length` — общее количество.
  - `items.filter(item => item.done).length` — количество выполненных.
  - `items.reduce((sum, item) => sum + item.price, 0)` — сумма (необязательно).
- **Главное правило:** с массивами всегда строй **НОВЫЙ** массив (spread / filter / map).
  Никогда не `push` / `splice` напрямую — это мутация, React не увидит.

## Тема 6. Условный рендеринг

- В React нет `v-if`. Вместо него — JS-выражения в `{ }` (как и везде в JSX).
- **Показать, если истина** (аналог `v-if`):
  ```jsx
  {isOpen && <Modal />}
  ```
  `&&` возвращает правую часть, только когда левая `true`; иначе ничего не рендерится.
- **Выбор из двух вариантов** (аналог `v-if / v-else`):
  ```jsx
  {cart.length === 0
    ? <p>Cart is empty</p>
    : cart.map(item => <div key={item.id}>{item.title}</div>)}
  ```
  Тернарник: `условие ? (да) : (нет)`.
- **Подводные камни:**
  - `{count && <X/>}` при `count === 0` покажет `0` (левая часть «ложная», но `&&`
    возвращает её как есть). Для чисел писать `count > 0 && <X/>` или `count ? <X/> : null`.
  - `if` прямо внутри JSX писать нельзя — только выражения (`&&`, `? :`, `.map`).
    `if` допустим в теле функции ДО `return`.
- **Где в витрине:** «Cart is empty» (len===0), кнопка показать/скрыть описание, переключатель табов.

## Тема 7. Формы и контролируемые инпуты

- **Контролируемый инпут** — значение хранится в состоянии (`useState`), а не в DOM.
  Меняем состояние через `onChange`, показываем через `value={...}`:
  ```jsx
  const [value, setValue] = useState('')
  <input value={value} onChange={e => setValue(e.target.value)} />
  ```
  `e.target.value` — текст, набранный в поле.
- **Форма и отправка:** `<form onSubmit={handleSubmit}>`. В обработчике обязательно
  `e.preventDefault()`, иначе страница перезагрузится:
  ```jsx
  function handleSubmit(e) {
    e.preventDefault()
    // что-то делаем с value
  }
  ```
- **Несколько полей:** либо отдельный `useState` на каждое, либо один объект
  `useState({ title: '', price: '' })` (обновляем через spread:
  `setValue({ ...value, title: e.target.value })`).
- **Подводные камни:**
  - Забыл `value={...}` → инпут «неконтролируемый», не обновляется от состояния.
  - Забыл `onChange` → React warning, инпут становится read-only.
  - В `onChange` пиши `setValue(e.target.value)`, а не `setValue(e)` (нужен `.value`).
  - В `onSubmit` не забудь `e.preventDefault()`.
- **Где в витрине:** поиск товара (инпут + фильтрация списка), форма добавления товара.
