# React-тренажёр: журнал обучения (верстальщик → React)

> **Агент-ментор:** при старте НОВОЙ сессии СНАЧАЛА прочитай этот файл целиком, чтобы
> восстановить контекст. Не начинай заново — продолжай с первой незавершённой темы в
> «Прогрессе по темам» и последней записи в «Краткой истории сессий».
> Ученик — продвинутый **верстальщик** (HTML/CSS/BEM/адаптив/доступность), новичок в React.
> Учим React **руками** через живой проект, не лекциями.

---

## Цель обучения

Научить верстальщика уверенно работать с React до уровня **strong junior / middle**
за адекватный отрезок времени. Без лекций — только практика руками через пет-проект.
Бизнес-логику (состояние, эффекты, данные) объясняем **с нуля, как новичку**; вёрстку/стили —
через параллели с Vue (`<style scoped>` → CSS Modules).

## Алгоритм обучения (единый цикл по КАЖДОЙ теме)

1. **Объяснение (1 раз).** Ментор описывает тему (живой пример, как сейчас): суть, синтаксис,
   подводные камни. Даём опорную точку, НЕ учим «вслепую».
2. **Совместный билд под диктовку (руками).** Ученик вручную создаёт компонент ПОД ДИКТОВКУ
   ментора: ментор диктует, ученик печатает/создаёт всё в файле и «щупает руками» синтаксис
   и механику темы. ОДИН компонент — чтобы снять страх и прочувствовать тему вместе.
   (Диктовка здесь допустима; в самих задачах — только ТЗ словами, без диктовки.)
3. **Проверка понимания (обязательный гейт).** Ментор спрашивает: «Понял ли тему?».
   - Если ДА → переходим к задачам (шаг 4).
   - Если НЕТ → задачи НЕ выдаём; ментор ещё разъясняет/показывает проблемное место и
     снова спрашивает. Никаких дальнейших шагов (задачи, контрольная) без подтверждения понимания.
4. **5 задач по очереди (самостоятельно).** Ментор даёт ТЗ СЛОВАМИ (без готового кода задачи;
   можно подсматривать в «Справочник синтаксиса»), ученик пишет САМ → ментор проверяет
   (`oxlint` обязателен exit 0 + разбор логики). Так 5 раз, от простого к чуть хитрее.
5. **Финальная контрольная работа.** Отдельная задача на тему, объединяющая пройденное
   в её рамках. БЕЗ новых тем (иначе это уже другая тема). Студент делает, ментор проверяет.
6. **Фиксация.** Все этапы (объяснение, совместный билд, проверка понимания, 5 задач,
   контрольная) записываются в этот файл (секция «Прогресс по темам») — чтобы не терять контекст.
7. **Переход к следующей теме** (от простого к сложному). В конце курса — **итоговое
   приложение на ВСЕ темы** (пет-проект «учебная витрина»).

**Важно (выверено на практике):**
- Массивы (`.map`, `spread`, `key`, `filter`) — ОТДЕЛЬНАЯ тема, а не «закрепление счётчиков».
  Не смешивать темы внутри контрольной работы.
- Темп: массивы, колбэки с аргументами, spread даются тяжело → паузы, пошаговость, не форсировать.
- `import { useState }` пишется В КАЖДОМ файле, где используется хук (импорты не наследуются
  из `App.jsx`; аналогия с импортом CSS-module).

## Профиль ученика

- **Бэкграунд:** продвинутый верстальщик (HTML/CSS/BEM/адаптив/доступность). Vue.js видел на
  уровне вёрстки/шаблонов и `<style scoped>`, НЕ писал на нём бизнес-логику.
- **Темп (выявлено):** концепции массивов, `.map`, колбэков с аргументами, spread-оператора
  даются тяжело. Не форсировать, объяснять пошагово, делать паузы между сложными шагами.
- **Эмоциональный барьер:** страх перед «шагом за верстку» в логику («слишком много надо знать»).
  Поддерживать, напоминать о пройденном, не форсировать новую логику, давать паузы и
  возвращаться к понятной вёрстке для уверенности.
- **Метод обучения (активное воспроизведение):** сначала ученик печатал код ПОД ДИКТОВКУ
  готовых примеров (не уверен в самостоятельном воспроизведении). Решено: ментор даёт ТЗ
  СЛОВАМИ, ученик пишет сам и сам решает структуру; ментор подсказывает только при застревании.
  Готовый код задачи НЕ диктуем. Уточнение по алгоритму обучения: диктовка допустима ТОЛЬКО
  на шаге «Совместный билд» (один компонент под диктовку, чтобы прочувствовать тему руками).
  Сами 5 задач и контрольная работа — строго самостоятельно (ТЗ словами, без готового кода).
- **Опора на синтаксис:** синтаксис React ещё не выучен наизусть. Дан **«Справочник синтаксиса»**
  (как словарь) — ученик пишет сам, подсматривая в него; точечные вопросы «как написать Х»
  ментор отвечает. Опору убирать постепенно.
- **Типичное заблуждение (вскрыто):** думал, что `import { useState }` нужен только в `App.jsx`.
  По факту КАЖДЫЙ файл с хуком импортирует его сам (модули изолированы).

- **Стилизация — опыт и предпочтения:** недавно работал с Vuetify (Vue) и его утилитарными
  классами; нашёл удобным utility-first подход. Значит, Tailwind в React будет ощущаться знакомо
  (а не чужеродно). Базовый выбор курса — CSS Modules + BEM — по-прежнему в силе; но при желании
   Tailwind — естественный для ученика вариант (как и React UI-кит вроде MUI — ближе всего к Vuetify).
- **Текст в примерах/задачах — английский:** договорились 2026-08-21 (лайблы кнопок и
  сообщений UI пишем на английском; код/комментарии — как есть).

### Шпаргалка Vue → React (для быстрого сопоставления)
| Концепт | Vue | React |
|---------|-----|-------|
| Изоляция стилей | `<style scoped>` (`data-v-*`) | CSS Modules (`import s` → `s.className`) |
| Состояние | `ref()`, `reactive()` | `useState()` |
| Условный рендер | `v-if` / `v-else` | `{cond && <X/>}` / `{cond ? A : B}` |
| Цикл | `v-for="i in items"` | `{items.map(i => <X key={i.id} />)}` |
| Событие | `@click="fn"` | `onClick={fn}` |
| Динамический атрибут | `:src="x"` | `src={x}` |
| Монтаж корня | `app.mount('#app')` | `createRoot(el).render(<App/>)` |
| Класс | `:class` | `className=` (строка/шаблон) |

## Справочник синтаксиса React (опора для самописа)

Держать перед глазами при самостоятельном написании. Это «грамматика», не готовые решения.

> Полные объяснения по пройденным темам (конспект «на вырост») — в отдельном файле
> `cheatsheet.md` (шпаргалка ученика). Он пополняется после каждой закрытой темы.

- **Импорт хука:** `import { useState } from 'react'`
- **Компонент (именованный):** `export function Name() { return ( <div/> ) }`
- **Состояние:** `const [count, setCount] = useState(0)` — `useState` возвращает МАССИВ из 2
  элементов: `count` = текущее значение (для вывода), `setCount` = ФУНКЦИЯ-сеттер. Меняем ТОЛЬКО
  через сеттер: `setCount(5)` (прямое значение) ИЛИ `setCount(prev => prev + 1)` (функция от
  старого, когда новое зависит от старого).
- **Изменить состояние:** `setCount(count + 1)` (НЕ `count = ...` напрямую).
- **Пропсы:** `function Card({ title }) { return <div>{title}</div> }` и `<Card title="Товар" />`.
- **Колбэк-пропс:** `<Card onAdd={fn} />`, внутри `onClick={() => onAdd(title, price)}`
  (обёртка-стрелка, чтобы передать свои аргументы).
- **Список (массив):** `items.map((item, i) => <div key={i}>{item.name}</div>)` — `key` обязателен.
- **Добавить в массив-состояние:** `setCart([...cart, { title, price }])` (через spread, не `push`).
- **Удалить из массива:** `setCart(cart.filter(item => item.id !== id))`.
- **Условный рендер:** `{cond ? <A/> : <B/>}` или `{cond && <A/>}`.
- **Класс:** `className="x"` (обычный) или `className={s.x}` (CSS Modules).
- **Событие:** `onClick={handler}` (без скобок — передаём ссылку на функцию).
- **Фрагмент:** `<> ... </>` — чтобы `return` вернул несколько элементов без лишнего `<div>`.
  Явная форма `<Fragment>` — когда нужен `key`.

## Целевое приложение (итог обучения)

Чему бы мы ни учились «по шагам», всё это — кирпичи одного здания. **Финал обучения = собранное
приложение**, в котором каждая пройденная тема применена на практике. Это не отдельное
«домашнее задание в конце», а наша северная звезда: по ходу курса мы примеряем очередной
паттерн на соответствующую часть приложения.

**Что строим:** учебная **витрина** (вариант Б пет-проекта) — небольшой интернет-магазинчик
на React. Макет знакомый, чтобы не тратить мозг на дизайн, а учить React.

**Структура (компоненты будущего приложения):**
- `App` — корень, собирает всё вместе.
- `Header` — шапка: название + счётчик корзины.
- `Tabs` — переключение разделов каталога.
- `ProductList` / `ProductCard` — список товаров.
- `Modal` — окно с деталями товара.
- `Cart` — корзина (уже делаем как контрольную по массивам).
- (позже) `Search`, страницы товара, провайдер корзины и т.п.

**Карта: тема → где применяем в витрине**

| Тема | Где применяем |
|------|---------------|
| 1. JSX | вся разметка компонентов |
| 2. Компоненты/пропсы | `ProductCard`, `Tabs`, композиция |
| 3. CSS Modules | стили всех компонентов (BEM) |
| 4. `useState` (счётчик) | счётчик корзины в `Header` |
| 5. Массивы | список товаров, корзина (добавление/удаление/счётчик) |
| 6. Условный рендер | `Tabs` (активный раздел), `Modal` (открыто/закрыто) |
| 7. Формы | поиск товара, добавление товара |
| 8. Подъём состояния | корзина поднимается из `Cart` в `App` |
| 9. `useEffect` | загрузка товаров (`fetch`) при старте |
| 10. `useContext` | проброс корзины без пропсов |
| 11. `useRef` | фокус в поле поиска, без перерисовки |
| 12. Кастомные хуки | `useCart`, `useProducts` |
| 13. Мемоизация | оптимизация списка товаров |
| 14. Router | страницы товара / корзины |
| 15. Тесты | проверка компонентов (Vitest + RTL) |
| 16. Деплой | выкладка на GitHub Pages |
| 18. Финал | собранное приложение целиком |

**Принцип:** каждую пройденную тему сразу примеряем на её место в витрине (хотя бы в контрольной
работе). В конце всё сходится в рабочее приложение.
